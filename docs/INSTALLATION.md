# First installation

HaxePress is a development preview and is not production-ready. The first-run wizard follows the administration interface's typography, palette and field conventions.

`make setup` prepares project-local dependencies and initializes `APP_KEY` through HxWell's native `generate:key` command, which is also used by `hxwell new`. It preserves a framework-created `.env` and its existing nonempty key. A missing environment file uses the CMS defaults with `APP_INSTALLED=false` and an empty `INSTALL_TRUSTED_IPS`; the key is generated by HxWell, and its CLI output is captured instead of printed. Setup does not create or print an initial administrator password. Direct `127.0.0.1` connections automatically open the wizard without configuring trusted IPs, including when that setting is missing or invalid. For other peers, configure trusted literal IPv4/IPv6 addresses explicitly, then build and start the site.

```dotenv
INSTALL_TRUSTED_IPS=192.0.2.10,::1
```

The built-in exception is exactly `127.0.0.1`, including its IPv4-mapped representation. Other `127.*` addresses and IPv6 `::1` still need an explicit entry; wildcard and hostname entries do not grant trust. A disallowed peer receives a locked warning before a session or fresh database connection is created. Client-submitted settings and forwarded identity headers cannot grant trust, including through a loopback proxy. Use a direct connection or an SSH tunnel for installation. The gate checks the actual peer address; it is not a generic reverse-proxy identity resolver.

The wizard is at `/admin/install`, so setup sessions keep the existing `/admin` cookie scope. Native session and CSRF middleware run only after the IP guard. Ordinary application routes, database migrations, plugins, scheduled jobs and MCP startup remain unavailable until installation completes. Static build assets still load so the locked screen is usable.

## Database

SQLite accepts a local `.sqlite` filename inside the `data` disk (`DATA_PATH`, by default `private/database`), not an arbitrary filesystem path. The database stays apart from `private/storage`, which holds uploaded files, installed plugins and themes, caches and sessions. Nothing under `private/` is served over HTTP; only `public/` is. MySQL accepts host, port, an existing empty database and credentials; the JVM runtime includes a pinned Connector/J driver. The native Schema API lists tables, then creates and drops a bounded probe table to verify DDL permissions. Nonempty databases are rejected rather than overwritten.

A successful check stores its configuration in the server-side setup session for ten minutes. Database passwords are never returned in page props or JSON summaries. The final step verifies the connection again; a browser-provided “verified” field has no effect.

The JVM MySQL compatibility patch uses the current JDBC driver name and finite connection/socket timeouts. JDBC uses column labels for aliases and normalizes numeric/timestamp values for native ORM casts. Native query identifiers are quoted for reserved names, MySQL text/JSON defaults use expression syntax, and foreign-key column types match unsigned auto-increment keys. SQL generation stays in framework compatibility patches; application and test code use native model/query builder and Schema APIs.

## Administrator and configuration

Choose a site name, administrator name/email and matching password of 12–72 bytes. Optional sample content is off by default. The native database initializer creates the schema and stores a password hash. Configuration output includes `APP_INSTALLED=true`, the selected database settings and site details. The administrator's name, e-mail and password are not written to `.env`: the account, with a hash of the password, lives only in the database.

The environment file is prepared with private visibility before initialization and atomically replaces `.env` after successful initialization. The web installer requires the existing environment file and cannot replace `APP_KEY`; that secret belongs to the HxWell project bootstrap. Other settings and comments are retained. Single-quoted values are literal, including `$`, `#`, quotes and backslashes, so credentials survive reload. The installer does not return these secrets to the browser or log credential values. The server-side database-check session record is removed on completion.

The first administrator is signed in with the explicit `admin` guard. Application services start without requiring a manual restart. On later requests and restarts the installation endpoints return 404. `ADMIN_NAME`, `ADMIN_EMAIL` and `ADMIN_PASSWORD` only create the first account of an installation made without the wizard; once an account exists, startup clears them from `.env`, including values earlier versions of the wizard left there. Use account management to change a password.

If initialization fails, the main environment file is not replaced. Use an empty writable database before retrying; partial tables from a failed external database initialization may require operator cleanup. The wizard does not delete an existing database automatically.

## Site backups

HaxePress installs the bundled **Backups** plugin on JVM sites using SQLite or MySQL. While the plugin is active, **Backup / Restore** is listed under **Extensions** in the menu, and **Settings** on the **Backups** card in **Plugins** opens it too. The Owner role has **Manage site backups** by default. Grant the capability separately in **Roles** to allow another administrator to prepare, verify, schedule and download backups. The menu entry needs only that capability; the Settings button is on the Plugins page, which needs **Manage themes and plugins**.

Use **Backup schedules** to set a fixed interval, optional first run, section selection, encryption and retention for each rule. For example, keep the latest five daily content backups and keep a separate weekly encrypted backup with plugins. The browser uses its local time when you pick the first run. The worker uses the saved interval after that and runs one overdue occurrence after downtime.

Scheduled files remain in private storage and can be downloaded repeatedly by administrators with the backup capability. The retention limit applies to each rule. Deleting a rule removes its saved files. Deactivating Backups from **Plugins** pauses its jobs and removes its admin page while preserving rules and retained files. Restoring is part of the same plugin: while a fresh site is not installed yet, the installer starts the bundled Backups plugin from its archive, and the plugin offers the restore step on the installation page.

Both plaintext and encrypted backups use `.hxpress`. The public header starts with `HXPRESS` and a zero byte. The following bytes record envelope version `2`, file type `1` for a site backup, encryption flag `0` or `1`, and the length of the UTF-8 CMS version. The version string and a four-byte big-endian ZIP length follow. Encrypted headers then include a 32-byte random salt. The installer checks the exact CMS version before opening the payload.

Every backup includes site settings, administrator accounts and shared media. Content, themes and plugins are independent selections. When plugins are excluded, their collections, content, packages, tables and jobs are omitted. Saved backup files are kept separately from the exported site data. The payload stores portable table definitions and bounded row streams, with per-item and archive MD5 checks. HaxePress rehearses each backup in an isolated SQLite database before making it available. Manual downloads expire after 15 minutes or are removed when the download closes.

Portable table definitions cannot carry SQLite `CHECK`, `COLLATE` or `DEFERRABLE` clauses. Early SQLite installations limited the content `status` column to draft and published with a `CHECK` constraint, which also rejects trashed and scheduled items. The first start of this release redefines that column without the constraint, keeping every row.

Choose **Encrypt with APP_KEY (.hxpress)** to encrypt the ZIP in authenticated 64 KiB frames. The original `APP_KEY` is required to open the file. Set it in the target `.env` before starting HaxePress. Losing the original key makes the archive permanently unrecoverable. The public header is authenticated as additional data with every encrypted frame.

Use **Verify backup** to rehearse an uploaded file. For an empty installation of the same HaxePress version, use **Restore a HaxePress backup**. The installer can create a new SQLite file or restore into a verified empty SQLite or MySQL database. **Skip damaged content items** recovers intact content and reports skipped IDs. Verification and restore send bounded chunks to private, session-bound staging and use disk streams for assembly and extraction.

## Existing installations

`APP_INSTALLED=true` preserves the ordinary application bootstrap. For installations predating that flag, an existing administrator record is detected through the native ORM and the installer remains closed. If an existing database cannot be verified, installation fails closed instead of treating an outage as a new site. Deployment backups retain `.env` and managed data.

## Verification

The same suite runs HxWell's actual `new` and `generate:key` commands in private temporary projects. It checks key uniqueness, private file permissions, repeat setup, preservation of existing keys/settings and retention of the framework key through web installation and restart. A missing environment file cannot be recreated by the web installer, and browser-supplied `APP_KEY` values are ignored.

`tests/installation.py` launches isolated JVM applications and covers the automatic `127.0.0.1` exception with missing/wrong/invalid configuration, explicit nonlocal and IPv6 trust rules, forwarded-header rejection, no blocked sessions or database files, CSRF, path validation, native database/DDL checks, administrator creation, optional sample content, private `.env`, literal password reload, disabled setup and restart/login. A real isolated MySQL server can also be exercised through `verify_mysql`; its database is created/dropped with the test-only native Schema fixture.
